03

Nine defects, root-caused and fixed

Every fix below is a genuine bug in the checking machinery or the composition, confirmed against real content before touching code — none are "the gate complained, so widen the gate."

2.1

Title-case check ignored its own internal-capitals rule

The docstring always said a word with internal capitals (glTF, macOS) counts as correctly cased; the code only checked the first letter. Fixed earlier the same day on a sibling mission — re-confirmed load-bearing here on headings like Certificate-Based (Public-Key) Encryption.

2.2

Format-name casing scanned inside fenced code and HTML tags

The inline-backtick stripper only consumed to the next backtick, so a triple-backtick fence left its entire body as "prose" — with 32 real TypeScript examples, a variable like const doc false-positived against the registry's DOC format entry. A literal <svg>/<img> tag name hit the same path.

FixStrip fenced code blocks and HTML tag names before scanning — a pure narrowing, verified to add zero findings on the other 30 candidates.
2.3

One-off ALL-CAPS emphasis words read as acronym claims

Verbatim prose used bare ALL-CAPS for emphasis the way most candidates use bold — IS, WHICH, PIXELS, each exactly once — colliding with ordinary lowercase uses elsewhere. A real acronym like SVG or PDF recurs 17–95× in this document; a one-off emphasis word doesn't.

FixAcronym-candidacy now requires ≥2 independent all-caps occurrences (or ≥3 distinct casing variants, to keep an existing glTF/GLTF/Gltf regression test green).
2.4

API-table stop-marker convention was never written down

The API Reference section's supplementary detail must be introduced with the exact heading #### Detailed Member Reference for the completeness checks to stop scanning there — real, working, portfolio-wide convention, but undocumented. A first-time composing agent invented its own label and produced 121 completeness findings from a 35 KB table being folded in as spurious extra "modules."

FixDocumentation gap, not a code bug — the skill doc now states the exact required heading.
2.5

The skill doc's own example violated its own heading-case gate

The composition guide illustrated <summary><strong>View Additional Examples</strong></summary> — copying it literally fails check_heading_title_case, because the regex extracts <strong> as part of the heading text.

FixCorrected the illustration to plain text, matching every already-shipped candidate.
2.6

TypeScript runner couldn't resolve a package's own self-import

pdf/typescript's Quick Start imports by its own declared package name — import { Document } from '@asposefoss/pdf' — not the relative-import convention other products use. Plain npm install only resolves a manifest's own listed dependencies; it never makes a package resolvable by its own name from inside its own source tree. Result on the first real end-to-end run: ERR_MODULE_NOT_FOUND on 86 of 91 real code blocks.

FixRun npm run build when the manifest declares it, then create a real filesystem symlink node_modules/{scope}/{name} → project dir — the same mechanism npm link uses internally. npm install . was tried first and confirmed to be a silent no-op.
2.7

Badge template mislabeled a Node.js constraint as a TypeScript version

The suggested language-version badge for any typescript-platform product read "TypeScript Version," but the underlying data (engines.node) is a runtime constraint, never the compiler/language version.

FixRelabeled "Node.js" with the real npm-ecosystem logo — inert on every currently-shipped candidate, but would have mislabeled the badge for the next typescript product to use it.
2.8

TypeScript runner had no fixture staging or example chaining

The Python runner earned both in a prior mission (ST-171); the TypeScript runner never did. After the self-import fix (2.6) landed, a real end-to-end run still failed 83 of 91 blocks — now with ReferenceError: doc is not defined instead of ERR_MODULE_NOT_FOUND. Root cause: the upstream README itself writes several long runs of ### sections as one continuous narrative sharing an ambient doc, not as independently-runnable snippets — real upstream authoring style, faithfully preserved verbatim.

FixReused the Python runner's own fixture-staging code unchanged (already language-agnostic) and added an import-based example-chaining heuristic for TypeScript. Result: 83 undifferentiated errors collapsed to 72 honest "depends on a named failed block" plus 11 individually-understood root causes.
2.9

No classifier distinguished a real upstream defect from an example mistake

One of the 11 root causes from 2.8 wasn't an ambient-scope issue: htmlFileToPdf is documented as importable from @asposefoss/pdf and is a real, exported function in the package's own src/node.ts — but the package's only real entry point, src/index.ts, never re-exports it. A real build + Node's ESM loader confirms the import genuinely cannot resolve.

FixAdded an UPSTREAM-BROKEN classifier (mirroring a Python-runner distinction that already existed) so this reports as a real upstream defect, not generic RUNTIME-ERROR — recorded with full evidence in upstream-issues.md.
