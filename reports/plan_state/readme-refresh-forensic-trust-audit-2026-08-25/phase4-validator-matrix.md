# Phase 4 (continued) — Merged Validator-Effectiveness Matrix, full 31-product portfolio

This supersedes the earlier 24-row/48-finding canary-only matrix. It merges those 24 rows
(updated with additional product hits and refined escape-cause analysis) with all findings
from the 24 subsequently-reviewed products (page/python, tex/python, 3d/java, 3d/typescript,
barcode/python, cells/cpp, cells/go, cells/java, cells/net, cells/python, cells/rust,
cells/typescript, email/cpp, email/net, email/python, font/python, html/python, pdf/python,
slides/cpp, slides/java, slides/net, slides/python, words/net, words/python) — covering the
full 31-product portfolio.

## Method

- Read all 24 new phase3-review files' Verdict + Stage C: Adversarial Verification sections in
  full (not summarized), extracting Stage C's *final* determination for every numbered finding:
  CONFIRMED findings (including UPGRADED-severity/scope ones) are kept as-is; DOWNGRADED findings
  are kept with the downgrade noted; UNCONFIRMED / fully REFUTED findings (e.g. page/python's
  upstream_baselines.json NIT, cells-java's u0013 excerpt-inconsistency claim, slides-python's
  "bypassed PR audit trail" sub-claim) are excluded from the count entirely, per the task brief.
  Purely positive/no-defect commentary (e.g. cells/cpp's item 6, words/python's "positive
  findings") is excluded from the finding count the same way the original 48 excluded it.
- Cross-referenced every new finding's defect *class* (not just its product) against the existing
  24-row matrix before deciding whether to fold it into an existing row (adding the new
  product(s) and refining the escape-cause/systemic-scope text where the new evidence changes it)
  or to open a new row. New rows were opened only where no existing row's mechanism matches, per
  the task's explicit examples (cells/java's Maven-version-currency gap, 3d/java's formats.py
  fabrication bug, slides/cpp's C++ internal-namespace leak, the "structure ledger has 1-13
  entries vs 20-30+ real headings" pattern) plus several more of the same character found during
  this pass (see rows 25-36 below).
- Where a new product's own Stage C performed a **portfolio-wide cross-check** (several of the 24
  new reviews did this spontaneously — e.g. cells/cpp's Nav-TOC grep across all 31 products,
  slides/java's structure-ledger entry-count sweep, cells/rust's publication-ledger pattern scan,
  slides-net's `verified_by_run_id` sweep), that cross-check's own numbers are used directly
  rather than re-derived, and are flagged as such.
