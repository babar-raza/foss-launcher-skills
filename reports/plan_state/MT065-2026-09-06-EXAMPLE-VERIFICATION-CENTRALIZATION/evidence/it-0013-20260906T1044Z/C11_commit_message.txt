feat(example-verification): C11 -- DotNetRunner: the second LanguageRunner protocol implementation (tier 1-3)

New scripts/pipeline/lib/example_verification/runners/dotnet.py:
DotNetRunner, the second concrete runners/base.py LanguageRunner
implementation after C5's GoRunner, applying that taskcard's own
independent-review lessons from the start rather than rediscovering them:

- canonical_lang="csharp", ceiling_tier=3.
- starts_chain: first non-comment line is `using` -- this repo's real
  Quick Start snippets are top-level-statement C# programs.
- acquire: real `dotnet new console --no-restore` scaffold -- a genuinely
  fallible step (unlike Go's, which never creates anything), reports
  {"ok": False} when the toolchain is missing or scaffolding fails.
  Attempts `dotnet add reference` against this product's own main .csproj
  (resolved via a locally-ported _select_main_csproj) when a real clone
  exists; a missing/failed reference is not an acquire failure -- a
  pure-BCL block needs no reference at all.
- compile/execute: real `dotnet build`/`dotnet run --no-build`.
- classify: a file-citation-basename check (does the error/exception cite
  a .cs file other than Program.cs), built this way from the start based
  on GoRunner's own review finding that a raw path-substring match never
  appears verbatim in real compiler output. Verified against two real,
  distinct .NET diagnostic formats confirmed via a manual probe before
  writing any code: MSBuild build errors
  ("Program.cs(1,19): error CS0103: ...") and unhandled-exception stack
  traces ("... in Program.cs:line 2").

_select_main_csproj ported (not imported) from dependency_extract.py,
matching that module's own documented "reimplemented locally" convention
and the plan's own fallback instruction.

New test_example_verification_dotnet.py (15 tests, skipped if dotnet isn't
on PATH, real subprocess calls throughout, ~26s): starts_chain (3),
classify (4), real acquire() -- a real scaffold with no reference for an
unknown family, and a genuine {"ok": False} when dotnet is removed from
PATH for one call (restored via try/finally) (2), real compile() via real
dotnet build -- clean pass + a genuine undefined-identifier error (2),
real execute() via real dotnet run -- clean pass + a genuine
divide-by-zero runtime exception (2), and two full
BaseRunner(DotNetRunner(...)).run(...) end-to-end proofs -- a clean block
reaching real proof_tier=3, and a broken block correctly classified
COMPILE-ERROR through the whole tier ladder (2). Full regression: this
file (15) + test_example_verification_runners_base.py +
test_platform_capability_matrix.py = 311 passed, 7 skipped (pre-existing,
unrelated), 0 failed. check_monkeypatch_lint.py: 0 violations.

Deliberately not touched: platform_capabilities.yaml's "net"
example_verification site is in C11's allowed_paths but left alone --
check_platform_capabilities.py:check_example_verification does an
exact-value diff of the YAML against

pilot against actual product content (needs fixture-staging support
neither Go nor .NET have yet -- a separable follow-on).
