fix(example-verification): C10 -- body_refresh verified-snippet selection fix

Rewrites _example_regeneration (the EXAMPLE_REGENERATION update strategy's
snippet-substitution logic) fixing two real bugs (RC21, both named in the
governing plan's own consumer-wiring row):

1. Hardcoded *.cs glob + unverified, filesystem-order-dependent selection.
   Candidates were selected via snippets_dir.glob("*.cs") regardless of
   the page's actual platform, in raw OS-dependent glob order, with the
   only check being "doesn't mention the old symbol" -- zero proof the
   "replacement" was ever real, promoted, upstream code. Now: a real
   per-platform extension map (verified against every platform with real
   snippet data on disk: net->.cs, python->.py, java->.java, cpp->.cpp,
   typescript->.ts, go->.go), sorted() iteration, and a hard requirement
   that the candidate have a code_sha256 entry in snippets_index (C6's
   real "verify at the source" content-hash proof).
2. Replaced the FIRST fence in the section, not the one containing the
   symbol. re.sub(..., count=1) blindly overwrote whichever code block
   came first -- proven, via a mechanical revert-and-rerun check, to be a
   REAL, live bug against this repo's actual knowledge/pdf/net/merged/
   snippets/ data: the old code substituted a real, unrelated test
   snippet in place of the expected removal marker. Now uses
   lib.example_verification.code_fences.enumerate_code_blocks (the
   canonical tokenizer) to find the specific block whose content contains
   the symbol, replacing only that one.

New keyword-only platform/snippets_index parameters (matching the plan's
own proposed signature); the one real call site now loads
snippets_index.json when one exists and threads both through.

Honest limit, disclosed (matching C5's L-15 precedent): the plan asks for
execution_proof.tier >= 2 as a hard filter, but no product's snippet
index has execution_proof populated anywhere yet (C6's own deferred post-
promote sweep). Hard-requiring it today would make this function ALWAYS
fall through to the removal marker for the whole portfolio -- a real
regression relative to even the buggy old behavior. code_sha256 is the
baseline verification bar instead; execution_proof.tier is read as an
additional ranking signal when present, never a hard gate.

8 new focused tests directly against _example_regeneration + a full
end-to-end regression guard. Full suite: 82 pre-existing + 8 new = 90
passed. Mechanically verified: reverted the fix via git stash, watched
all 8 new tests fail -- including the end-to-end guard showing the real
pipeline against real pdf/net snippet data silently substituting an
unrelated real snippet instead of the expected removal marker, proving
bug #2 live, not theoretical -- restored the fix, confirmed 90/90 pass
again.

check_monkeypatch_lint.py: 1 pre-existing T2 violation at
test_body_refresh.py:412, a different, untouched test -- not introduced
by this change.

Deliberately not touched: _fenced_code_blocks/_code_block_structure_shifted
(the other fence parser in this file) -- out of C10's own stated scope,
uses the canonical tokenizer directly for its own new logic instead.
