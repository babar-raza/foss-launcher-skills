feat(example-verification): C6 -- snippet code_sha256 + exact-hash provenance + L-15 real-proof read

Snippet promotion, verify-at-the-source design (governing plan's Round 4
Decision 6): every snippet promote.py copies from scout/ to merged/ now
carries a deterministic code_sha256 (exact + norm) hash, computed from the
copied file's own text -- no execution inside promote() (it runs under
acquire_regen_lock with an atomic staging swap; 6 test_promote_*.py suites
call it for real and stay green unchanged). norm uses
lib.example_verification.code_fences.normalize_content, the same
normalization CodeBlock.sha256_norm uses, so a page's own code block can
inherit this proof by exact hash even after cosmetic drift (indentation,
line endings).

Two consumers rewritten to use it:

- audit/snippets.py:verify_snippet_coverage -- was a fuzzy
  classes_used/methods_used token-intersection heuristic; now an exact
  sha256_norm lookup into the snippet index, using
  lib.example_verification.code_fences.enumerate_code_blocks (the canonical
  tokenizer) instead of this file's own ad hoc ``` -toggle state machine
  (one of the ~40 duplicate fence parsers RC19 catalogued). SKIPs loudly
  (one INFO finding) when a product's index has no code_sha256 yet, per the
  plan's explicit design, rather than falling back to the heuristic it
  replaces. Still default-off (audit/runner.py --check-snippets, unchanged)
  -- the plan says flip it on only after a portfolio sweep populates
  code_sha256, which hasn't run yet (see commit message footer). The old
  heuristic function (_check_code_block_snippets) is kept, unused, only
  because audit/__init__.py re-exports it by name and that file is outside
  this taskcard's allowed_paths.

- launch_gate.py:gate_l15_snippet_syntax -- reads each snippet's
  execution_proof.tier against PLATFORM_CONTRACT[platform].max_tier when
  present (WARN on any proven snippet below contract tier; unproven entries
  don't count against a partial sweep). Falls back UNCHANGED to the
  original +/-2 bracket-balance heuristic when no entry has execution_proof
  yet -- true for every product today, since the sweep hasn't run anywhere.
  This deliberately deviates from the plan's literal "SKIP if absent"
  wording: L-15 is a real, currently-active launch gate, and a blanket SKIP
  portfolio-wide today would silently weaken a live gate rather than
  rewrite it (the same "keep old and new, no regression" posture C3 used
  for the same reason). test_gate_l01_l07.py::TestGateL15SnippetSyntax
  (outside this taskcard's allowed_paths) passes unchanged, proving the
  fallback is byte-identical to the pre-existing behavior.
