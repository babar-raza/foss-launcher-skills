## Deeper reassessment — production framing (added on the second pass)

The list above is accurate but it is a list of **symptoms**. Treated as a patch list it would be the fifth consecutive launch (rust MT010 C1-C4, go MT011, cpp MT012, python MT013 "no hardening expected — 3 bugs anyway", now TypeScript ×11) where platform defects are discovered live, per product, after the knowledge is already built. The pattern itself is the production problem. This section separates what is visible from what causes it, states what actually breaks consistency across reruns (with the evidence strength for each claim), and says what to preserve versus redesign. The G-TS/G-SK cards above are kept — as *instances* of the structural fixes below, not as the design.

### What actually breaks consistency across reruns (evidence-graded)

1. **Snippet eviction changes the page set.** `site_planner.detect_clusters` derives per-cluster `snippet_count` from `snippet_index.classes_used` (L921-931) and the optional deep-dive blog post / dev-guide eligibility use snippet thresholds; the 100-cap is filled in directory-then-alphabetical order (W4). Adding one upstream test file can evict example snippets → a cluster drops below threshold → the *site plan* (page list) differs on the next refresh. Mechanism verified in code; not yet observed live on a single product (medium confidence). Content code-block provenance itself is matched by class/method token overlap (`audit/snippets.py` L70-98, advisory INFO), so positional renumbering is harmless — the drift is in *which* snippets exist, not their IDs.
2. **Grouping keyed on paths (W5).** Any upstream directory rename or move re-groups the reference index and re-clusters docs/KB; for flat layouts the grouping is degenerate from the start. `GROUPED_INDEX_GENERATOR_VERSION` exists (good — a versioned contract) but only for the reference side.
3. **Hash blind spots (W8).** A rerun after a `tree_helpers.py` change produces different `api_surface.json` with the same `extractor_hash` → `no-op` detection (S-13/S-94/refresh_run) can report "unchanged" while output changed, or re-stamp evidence for no reason (cf. MT033-FANOUT's 962 dirty files).
4. **Registry disagreement (W6).** `active:true` + exclusion entry → S-49/S-84/reconcile/site planner each decide "live?" differently depending on which file they read (owned by `TC-MT039-13`).
5. **Prose-executed launch (W7).** Two agents running S-49 on the same inputs can produce different page sets (blog index present or not, websites synced or not) because steps live in mission memory, not in the skill.
6. **Inherent, not fixable by design:** LLM enrichment (ERC claims) and agent-authored prose vary between runs. The system already bounds this with evidence frontmatter, deterministic evaluators and the no-downgrade guard; the design below keeps the *deterministic* layers (extraction, planning, reference generation, evaluation) byte-stable across reruns and makes the variable layer's inputs pinned and its outputs gated — it does not promise identical prose.

### Preserve vs redesign

**Preserve (works, proven, byte-parity tested):** the tree-sitter extraction engine and its per-language maps as the *implementation*; `refresh_run.py`'s state machine and manifest shape; `package_registry.json` + the `package-install`/`maven-*`/`cargo-crate` shortcodes; `GROUPED_INDEX_GENERATOR_VERSION` versioning; PY-SHIM discard semantics; the evidence/frontmatter contract and `member_validity`'s `reachable` check; the S-90/H-gate and 16-gate structure; `data/registry_exclusions.json`; the seam (`configure()`) test pattern; the one-test-file-per-fix convention; the isolated-index commit tooling.

**Redesign (structural, generic, versioned):** (D-1) platform capability coverage becomes a declared contract with a matrix test over all platforms plus a declaration-kind census; (D-2) knowledge acceptance gains a fidelity gate computed from independent probes; (D-3) language semantics become adapters with declared capabilities (export surface, doc comments, declaration kinds), consumed once by scout, evaluator and reference filter; (D-4) module/topic assignment moves into the knowledge layer and is consumed by both the site planner and the reference index; (D-5) snippet selection becomes a deterministic tiered budget independent of iteration order; (D-6) format signals come from one identifier-word recognizer; (D-7) product identity/liveness has one loader; (D-8) the launch gets pinned inputs, a skill-doc↔code pinning check, and a path toward a run-bound `launch` mode. Every redesign is additive behind a version or config switch so shipped products change only at their own next refresh.

## Durable design — D-1 … D-8 (implementation directions, validation, regression controls)

Each item names: the change, why it is generic (not TS-local), validation, regression control, tradeoff. The G-TS cards are the TypeScript instances of D-1..D-7 and stay as written; the new TC-MT040-40..48 cards below own the generic layer.

**D-1 Platform Capability Contract + conformance matrix (owns G-TS-09, generalises `test_rust_platform_maps.py`).** New `scripts/pipeline/config/platform_capabilities.yaml`: for every platform in `data/platforms.json` that has ≥1 product in `data/products.json`, a declared row per capability site (class kinds, func kinds, module kinds, doc style, install parser, package-manager set, fence langs, foreign/prose patterns, primary lang, code-syntax parser, smoke-test langs, KB suffix, trouble-platform flag, coverage policy, case convention, reachability adapter, format recogniser style) with the value or an explicit `n/a: <reason>`. New `tests/test_platform_capability_matrix.py` parametrised over (platform × site) asserting the code map agrees with the declaration (no undeclared gaps, no silent `n/a`). **Declaration-kind census (generic version of G-TS-12):** a test that parses each platform's fixture package AND, when present, the real clone-cache root of one registered product, collects top-level/exported declaration node types actually observed, and asserts they are ⊆ (handled ∪ declared-ignored) — this is what would have caught `abstract_class_declaration` for TS and catches the next unmapped kind in any grammar. Validation: matrix green for all 8 platforms with products; census green on 3d/typescript, cells/rust, pdf/python clones. Regression control: adding a platform or a capability site without a declaration fails CI (wire into `scripts/ci/checks/` as a check; `test_rust_platform_maps.py` stays, the matrix must reproduce every assertion it makes). Tradeoff: one more data file to keep honest — mitigated because the test, not a human, keeps it honest.

**D-2 Extraction Fidelity Gate (owns W3; makes G-TS-12/08/11/04 detectable before content).** New `scripts/pipeline/commands/knowledge/scout_fidelity.py` run by S-54 after scout and by `readiness_gate.py` as **G-08**, writing `scout/fidelity_report.json` and summary fields into `scout_report.json` (extend `validate_scout_output.py`). Probes, all cheap and language-adapted through D-3: **P1 declaration census** (public/exported declarations per kind counted from source vs entries in `api_surface.json`; ratio and a named diff); **P2 entry-point coverage** (names exported by the language's entry-point adapter ⊆ api_surface names; reports missing and `reachable:false`-but-exported inconsistencies — this is G-TS-10's barrel check made generic: `__all__`, `pub use`, barrel, Go exported identifiers, C# public); **P3 doc-comment census** (declarations preceded by a doc comment in source vs entries with non-empty `doc`; a source with ≥N doc comments and 0 captured is a FAIL); **P4 README/manifest format cross-check** (format tokens named in README headings/feature bullets and package keywords vs `formats.json`; WARN with named misses; FAIL only when README names ≥3 formats and `formats.json` has 0 for that family's primary format); **P5 snippet provenance** (distribution by source tier; FAIL when curated example/README tiers exist in the repo but contribute 0). Thresholds start **advisory (WARN)**, calibrated by running the gate over all 31 products and recording the distribution (`reports/sprint/pdf-typescript-hardening/evidence/fidelity_calibration.json`) before any FAIL threshold is enabled; FAIL enabled per probe only where the calibration shows zero false positives on the current fleet. §7d text gains "and `scout_fidelity` reports no FAIL" (AGENTS.md is human-only — record the proposed wording in the mission for the operator; enforce in code via G-08 and the S-54/S-49 skill docs). Validation: fixture packages that deliberately hide an abstract class / a doc comment / an example dir must FAIL the corresponding probe; the current 3d/typescript scout must FAIL P1 (8 abstract classes) and P5, and pass after C1/C2 re-scout. Regression control: a golden `fidelity_report.json` per fixture; the fleet calibration file is diffed on every extraction change. Tradeoff/limit: probes are heuristic (regex/tree-sitter census, not a compiler); they detect *systematic* omissions, not individual mis-parses — say so in the report header. Honest confidence: high that P1/P3/P5 would have caught this launch's scout-side gaps (each is an exact count comparison); medium for P4 (README wording varies).

**D-3 Language adapters with declared capabilities (owns G-TS-02a/b/c, 08, 12; W2).** Introduce `scripts/pipeline/extraction/lang/` with one module per language exposing a small, typed interface used by scout, evaluator and reference filter alike: `declaration_kinds()`, `doc_anchor(node)` (the generic export-wrapper fix — TS/JS `export_statement`; verify Rust `attribute_item`/Python decorated definitions while implementing), `parse_doc(raw) -> DocBlock(summary, params, returns, remarks, examples, deprecated)` per doc style (`xml_doc`, `javadoc`, `jsdoc`, `docstring`, `rustdoc`), `export_surface(repo, pkg_root) -> ExportSurface | Unknown` (python `__all__` and rust `pub use` moved here from `api_surface.py` unchanged; TS barrel new; Go = exported-identifier rule; C# = `internal` scan moved from `_reachability.py`; cpp/java = `Unknown` declared). `api_surface._compute_reachable`, `_reachability.live_unreachable` and `reference_filter._passes_platform_scope` consume the adapter — one implementation, three consumers. Reference-side policy: `REACHABILITY_ENFORCED_PLATFORMS` (config, versioned with a `REFERENCE_FILTER_POLICY_VERSION` bump) — TS/JS enabled now; python/rust listed as "enable at next refresh of each product" so shipped page sets change only under their own refresh run (supersedes first-pass Decision 4's TS-only hard-code with a declared, testable policy). Validation: adapter contract tests per language (fixture packages incl. `ts_flat_package`); byte-identical `api_surface.json` for the existing python/rust fixtures before/after the move (golden files). Regression control: golden scout outputs for every fixture package under `tests/fixtures/`, compared on every extraction change (new `tests/test_extraction_goldens.py`). Tradeoff: a refactor of ~200 lines of working code into modules — mitigated by goldens; limit: regex barrel parsing cannot follow computed exports or `export * as ns` (declared `Unknown` → fail-safe, never flags).

**D-4 Module/topic assignment in the knowledge layer (owns G-TS-01 and the site-planner half of W5).** At promote time write `module_key` and `module_label` onto every `api_surface` entry using one ordered strategy: (1) informative directory segment relative to the package root (today's behaviour for nested layouts), (2) export-group from the entry-point adapter when the barrel/`__init__`/`lib.rs` groups re-exports (TS barrels and Python `__init__` files usually do), (3) family-agnostic stem-keyword table for flat layouts (the G-TS-01 table), (4) `core`. `MODULE_ASSIGNMENT_VERSION` recorded in `model.yaml`; `batch_reference._derive_group_key` and `site_planner._class_to_subpackage` both read `module_key` when present and fall back to today's logic when absent (older knowledge). Validation: expected group sets for 3d/typescript (7 groups), cells/typescript (2), pdf/python (unchanged vs today — golden), pdf/typescript (keyword groups) and `detect_clusters` producing ≥4 clusters on the flat fixture. Regression control: `GROUPED_INDEX_GENERATOR_VERSION` bump + golden grouped-index bodies for two shipped products; site-plan golden for pdf/python must be byte-identical. Tradeoff: two consumers change at once; limit: keyword tables are presentational vocabulary — unknown stems degrade to `core`, never to fabricated groups.

**D-5 Deterministic snippet selection (owns G-TS-04; W4).** Replace cap-by-iteration with a **tiered budget**: README fences (tier 0, ≤10) → curated examples/samples (tier 1, ≤60) → tests (tier 2, remainder), each tier sorted by (product-affinity, path, line), leaf-only test blocks, non-test files under test dirs excluded, `MAX_SNIPPETS` unchanged. Add `snippet_key` (sha256 of `source_file|source_function|normalised code`) to every entry — positional `snippet_NNN` IDs are retained for all consumers (promote renumbers anyway, L819) but the key makes eviction/addition diffs explicit in `merge_report.md`. Language-agnostic by construction; to avoid changing shipped products' snippet sets, the tiered order is enabled per platform via `platform_capabilities.yaml` (TS/JS now; others opt in at their next refresh, exactly like D-3's policy). ### Preserve vs redesign (remediation)

**Preserve:** `refresh_run.py` as the only execution path for shipped products (its `--rebuild-all` full-candidate reference scope, content-coverage before/after, page-impact matrix, locale-staleness sizing, S-107 handoff are exactly the right mechanisms); S-105 body-refresh as the primary deterministic body editor with S-20 as logged fallback; S-55 no-downgrade guard; `auto_updatable:false` as an unconditional block; S-75 locale-patch for <3-sentence changes; RG-004 locale topology check; `TC-STALE-001` `claim_delta` semantics.

**Redesign (additive, versioned):** (R-1) bind acceptance artifacts to their inputs and regenerate product state as a projection; (R-2) convert the existing analysis into expectation files consumed by the fidelity gate and by taskcard acceptance checks; (R-3) run remediation only as `refresh_run --mode combined` (re-scout with the hardened extractor + full reference rebuild + body refresh + validation + S-90 + bind-commit), one product at a time, gated on MT039's must-fix refresh gaps; (R-4) make locale handling decide by *content* change, never by evidence staleness alone; (R-5) harvest curation into generator inputs and resolve the `manual-edit-skill`/`auto_updatable` ambiguity explicitly; (R-6) give exclusions an evidence-bound re-check and resolve cells' liveness before touching its content.

### Tradeoffs, limits and confidence (deeper pass — stated plainly)

- **Scope and time.** The structural layer roughly doubles the hardening work (≈9 additional cards, several new modules). The alternative — patching the 11 TS gaps only — would ship pdf/typescript sooner and leave the next platform launch to rediscover the same class of defects live. This plan chooses the durable route; if time-boxing is required, D-1, D-2 and D-3 are the minimum that changes the failure mode (detect before content); D-4/D-5/D-6 can follow as their own cards without blocking the launch, at the cost of launching with the first-pass TS-local fixes for grouping/snippets/formats.
- **Heuristics remain heuristics.** Fidelity probes and format recognisers are census/identifier based; they catch systematic omissions (the class of every defect found in five launches), not individual mis-parses. A compiler-backed check for TypeScript (`tsc --noEmit` over snippets, barrel resolution through the real module graph) would be stronger but adds a Node toolchain dependency to the pipeline and CI runners; recommended as an optional WARN-level gate when `node` is present, not as a requirement.
- **Opt-in policies delay consistency for shipped products.** D-3/D-4/D-5 enforcement for python/rust/others happens at their next refresh; until then the fleet is intentionally heterogeneous. This is the price of "do not weaken what already works".
- **One-time fleet churn.** Widening `extractor_hash` and bumping `MODULE_ASSIGNMENT_VERSION`/`GROUPED_INDEX_GENERATOR_VERSION` makes every product read as needing re-scout / re-index once. Accepted and recorded in the change-trigger matrix; it is the honest signal, not a regression.
- **MT039 coupling.** Three items are shared; if MT039 opens first and designs them differently, this mission defers to it (durable state lives in each mission's `taskcards.jsonl`, and the shared cards carry both ids).
- **Confidence grading.** Strong (parse/count-verified): abstract-class blindness, export-anchor doc loss, snippet starvation on 3d/typescript, missing map entries, `refresh_run` cannot start a launch, `extractor_hash` covers 4 files. Medium (code-read prediction, not yet observed on the real clone): pdf/typescript formats under-detection, flat-layout cluster collapse in `detect_clusters`, snippet-eviction → site-plan drift. Weak/unknown until the clone lands: exact barrel resolvability, `test/helpers` contents, how many classes are internal. The plan's live pre-scan (TC-01) and baseline bootstrap (TC-02) exist precisely to convert the medium/weak items into measured facts before any code is written against them.
- **What this cannot guarantee.** Identical agent-authored prose across reruns; correctness of upstream code; that a future grammar introduces a node kind the census cannot classify — the census will report it as unclassified (fail closed), which is the intended behaviour.
