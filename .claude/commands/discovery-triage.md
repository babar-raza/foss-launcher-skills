## Purpose

Read patrol and sweep reports and create structured backlog items for every finding; routes all
discoveries and upstream changes to operator-reviewed backlog items and never directly invokes
S-12 or S-84 in MVP.

## IMPORTANT: Triage-First Mandate

**This skill NEVER directly invokes S-12 or S-84 in MVP.**

All findings route to backlog items. The operator reviews backlog items and manually invokes
S-84 per product. Direct S-84 dispatch is gated behind TC-GATE-01 (post-pilot rollout gate).

## When to use

After running S-102 (/repo-patrol) and/or S-103 (/change-sweep), run this skill to route
findings into the backlog.

## Pre-conditions

- `reports/discovery/patrol_report.json` exists (generated by S-102 `/repo-patrol`) **and/or**
- `reports/discovery/sweep_report.json` exists (generated by S-103 `/change-sweep`)

At least one report file must exist to proceed.

## Steps

1. Read the patrol report (if it exists):
   `reports/discovery/patrol_report.json`

2. Read the sweep report (if it exists):
   `reports/discovery/sweep_report.json`

3. For each entry in patrol_report["new_candidates"]:
   - action = "launch_candidate" (confidence >= 0.70): Create backlog item P1, Cat=K, Effect=KF, Size=L
   - action = "investigate" (confidence 0.40-0.69): Create INV-item P2
   - Record item in backlog/inbox.md using S-98 format

4. For each entry in patrol_report["status_changes"]:
   - change = "newly_archived": Create INV-item P2 -- "Archived repo: {family}/{platform}"
   - change = "gone_inactive": Create INV-item P3 -- "Inactive repo: {family}/{platform}"

5. For each entry in sweep_report["changed"]:
   - impact = HIGH: Create backlog item P1, Cat=K, Effect=TF -- "{family}/{platform} upstream change (HIGH)"
   - impact = MEDIUM: Create backlog item P2, Cat=K, Effect=TF
   - impact = LOW: Log in session output only; no backlog item

6. For each entry in patrol_report["unclassifiable"] that looks plausible (agent discretion):
   Create INV-item P3 -- "Unclassifiable repo: {repo_name}"

7. Set deferred discovery candidates with review date: after 30 days from today.

## Follow-Up Policy for Deferred Candidates

Candidates deferred via backlog triage use date-based review (30 days from deferral).
They surface at session-start via the existing briefing mechanism (CONVENTIONS.md deferred review).

## Post-Pilot Gate (TC-GATE-01)

After 3 successful triage cycles with correct routing, operator may enable --auto-refresh.
With --auto-refresh and HIGH+MEDIUM count <= 3: invoke S-12 then S-84 sequentially.
With --auto-refresh and count > 3: still create backlog items.
This gate must be explicitly approved by the operator.
