# Hard Stop Recovery Protocols

Recovery procedures for each unconditional halt defined in AGENTS.md S7.
Generated by TC-GOV-07 (Governance Simplification Sprint v3).

---

### 1. Path Guard Returns DENY

**Trigger**: S-01 (path_guard.py) returns DENY for a write target.

**Diagnostic**:
```bash
.venv/Scripts/python scripts/pipeline/commands/governance/path_guard.py <relative-path>
```

**Recovery**:
- If the path is in the allowlist but mistyped: correct the path.
- If the path is forbidden (themes/, layouts/, configs/, AGENTS.md, CLAUDE.md): request an override token from the operator.
  ```bash
  .venv/Scripts/python scripts/pipeline/commands/governance/override_manager.py create \
    --path <file> --reason "<reason>"
  ```
- If the file should be in the allowlist: update `scripts/pipeline/commands/governance/path_guard.py` allowlist (requires operator authorization + governance maintenance mode).

**Override Possible**: Yes (override token system)
**Escalation**: If override token is rejected, stop and report to operator.

### 2. Content-Check Returns FAIL After 2 Retries

**Trigger**: S-23 (content-check / audit.py) returns FAIL findings after 2 fix-and-recheck cycles.

**Diagnostic**:
```bash
.venv/Scripts/python scripts/pipeline/commands/content/audit.py <content-file>
```

**Recovery**:
- Review the specific FAIL findings in the audit output.
- Common causes: incorrect API references, missing evidence block, malformed frontmatter.
- Fix each FAIL finding individually and rerun audit.
- If the FAIL is a false positive (audit rule is wrong): report to operator with the specific rule ID and evidence.

**Override Possible**: No (content quality is non-negotiable)
**Escalation**: Report the specific failing rule, the file, and why you believe it's a false positive.

### 3. API Confidence = "low"

**Trigger**: Knowledge enrichment or content generation produces an API claim with confidence below threshold.

**Diagnostic**:
```bash
# Check the enriched claims for the product
cat knowledge/<family>/<platform>/scout/enriched_claims.json | \
  .venv/Scripts/python -c "import json,sys; [print(c) for c in json.load(sys.stdin) if c.get('confidence')=='low']"
```

**Recovery**:
- Verify the API claim against the actual source code in the clone cache.
- If the API exists but enrichment missed it: re-run `/knowledge-enrich` with updated source.
- If the API does not exist: remove the claim and regenerate content without it.
- If confidence is borderline: provide additional source evidence (file path, line number) to raise confidence.

**Override Possible**: No (API accuracy is non-negotiable)
**Escalation**: Report the specific API member, expected location in source, and enrichment output.

### 4. Page Grade = F

**Trigger**: Content evaluation assigns grade F to a page.

**Diagnostic**:
```bash
.venv/Scripts/python scripts/pipeline/content_eval/cli.py evaluate <content-file>
```

**Recovery**:
- Review the evaluation rubric output for specific failing criteria.
- Common causes: missing required sections, incorrect information, broken structure.
- Address each failing criterion and re-evaluate.
- If the page is fundamentally flawed: consider `/page-draft` to regenerate from knowledge.

**Override Possible**: No (grade F means the page would harm users)
**Escalation**: Report the specific evaluation criteria that failed and whether knowledge is insufficient.

### 5. Manual Blog File Creation

**Trigger**: Attempt to create a file under `content/blog.aspose.org/` without using `/new-blog-post` (S-56).

**Diagnostic**:
The write path hook or skill context hook will block the creation.

**Recovery**:
- Use `/new-blog-post` skill which handles the correct file structure, frontmatter template, and skill attribution.
- If the skill doesn't cover your use case: report the gap via gap escalation protocol (AGENTS.md S6b).

**Override Possible**: No (blog posts require specific structure)
**Escalation**: Report what kind of blog content you need and why the existing skill doesn't cover it.

### 6. PARTIAL/NONE Work Without Gap Escalation

**Trigger**: Agent attempts to do work classified as PARTIAL or NONE coverage without first running the gap escalation protocol.

**Diagnostic**:
Check if a registered skill covers the intended work:
```bash
# Search AGENTS.md S12 registry for matching skill
grep -n "S-[0-9]" AGENTS.md | grep -i "<keyword>"
```

**Recovery**:
- If a skill exists but was missed: invoke the correct skill.
- If no skill covers the work: invoke gap escalation (AGENTS.md S6b):
  1. Document the gap in `backlog/` using `/backlog`.
  2. Wait for operator to register a new skill or authorize ad-hoc work.
  3. Do not proceed without skill coverage or explicit operator authorization.

**Override Possible**: Only with operator authorization for ad-hoc work.
**Escalation**: Create a backlog entry describing the uncovered work pattern.

### 7. Required Upstream Skill Returns STOP/DENY

**Trigger**: A skill in the DAR dependency chain (AGENTS.md S6) returns STOP or DENY status.

**Diagnostic**:
```bash
# Check the skill run record for the failing skill
.venv/Scripts/python scripts/pipeline/commands/ops/skill_run_manager.py find-pending
```

**Recovery**:
- Identify which upstream skill failed and why.
- If the upstream failure is transient (network, timeout): retry the upstream skill.
- If the upstream failure is structural (missing knowledge, wrong input): fix the upstream issue first, then retry the dependency chain.
- If the upstream skill is broken: report to operator with the skill ID and error.

**Override Possible**: No (dependency chain exists for data integrity)
**Escalation**: Report the full dependency chain, which skill failed, and the error output.

---

## General Recovery Principles

1. **Never bypass safety checks** — hard stops exist because the alternative is worse.
2. **Diagnose before escalating** — run the diagnostic command and include its output.
3. **Operator authorization is required** — for any recovery that involves overrides.
4. **Document the recovery** — include the hard stop trigger and resolution in the commit message.
5. **Report false positives** — if a hard stop fires incorrectly, report it so the rule can be improved.
